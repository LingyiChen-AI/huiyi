# 发布说明

发版前先写好 `release-notes/v<版本号>.md`，再跑 `scripts/release.ps1 <版本号>`（没有这个文件脚本会停下；确实要用提交标题自动生成时加 `-AutoNotes`）。

发版的 CI（`.github/workflows/release.yml`）拿这个文件生成两份说明：

- **GitHub 发布页**：这份说明 + 下载 + 折叠起来的全部提交 + 完整对比链接。
- **应用内「发现新版本」弹窗**（打进更新包）：同样的条目，去掉链接和提交列表。

## 怎么写

参考 [Orca 的发布说明](https://github.com/stablyai/orca/releases/tag/v1.4.272)，一律中文：

```markdown
## 一句话概括这次更新最重要的变化 ✨

- 💬 **用户得到什么，一句话加粗。** 再用一两句说清楚具体表现、在哪里打开。[改动名](提交链接) · [改动名](提交链接)
- 🐛 **修复按「不再……」写。** 说明在什么场景下出现、现在怎样。[修复](提交链接)
- ⚙️ **设置项写完整路径。** 例如「设置 › AI 服务 › 纪要」里的「开会时实时整理纪要」。[设置](提交链接)
```

- 只写用户能感知的变化，按重要性排，3～6 条；同一个问题来回改了几轮，只写最终效果，撤回的做法不写。
- 每条一个 emoji 开头，先写收益再写细节，不写实现细节。
- 链接放在每条末尾（应用内弹窗会把末尾的链接去掉），多个用 ` · ` 隔开；提交链接用完整哈希：`https://github.com/LingyiChen-AI/huiyi/commit/<sha>`。
- 不用写「下载」和「完整改动」，CI 会自动加上。
